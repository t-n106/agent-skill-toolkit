# Problem Solving

Apply within the user/host task boundary; this skill adds no authority. Use the current task context when no separate orchestration layer exists.

## Method
1. Identify the unresolved question, established facts, constraints, and plausible explanations. Keep hypotheses distinct from observations; preserve useful failed attempts as `attempt → result → implication`.
2. Reason while existing evidence can change the next action. Otherwise choose the cheapest safe observation that distinguishes plausible explanations, considering information gain, cost, availability, and reversibility.
3. Update from the result. If reasoning, experiments, or fixes stop producing information, change assumptions, observation method, or decomposition rather than repeat the same loop.
4. Understand enough surrounding context to avoid a local but incorrect fix. Apply the minimum sufficient intervention; separate necessary changes from unrelated improvements.
5. Verify the intended outcome with evidence that could reveal failure. If evidence is unavailable or disproportionate, state what remains uncertain and its effect on the next action.

## Composition and completion
Use `research` for a substantive source-acquisition problem, `analysis` for evidence interpretation, and `debugging` for software-specific diagnosis. These are conditional methods, not mandatory prerequisites or follow-up stages. A parent may frame uncertainty while an execution owner solves a different local uncertainty; reuse settled facts instead of repeating the same investigation.

This skill does not authorize delegation. Finish when the justified intervention and its evidence answer the active question, or return the specific evidence/authority blocker with useful work completed.
