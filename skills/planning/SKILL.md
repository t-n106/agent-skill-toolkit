# Planning

Apply within the user/host task boundary; this skill adds no authority. Use the current task context when no separate orchestration layer exists.

## Build and maintain the plan
1. Work backward from the accepted outcome and acceptance evidence using current state, scope, protected behavior, and settled design decisions.
2. Identify the minimum dependency chain. Resolve uncertainty early when it can invalidate substantial downstream work, especially before irreversible commitments. Defer uncertainty that does not affect the next justified step.
3. Prefer thin observable end-to-end outcomes when useful; do not force vertical slices onto bounded research or infrastructure work.
4. Sequence independent work without unnecessary serialization. Parallel execution still requires host authorization and a worthwhile integration cost.
5. For each meaningful unit, state outcome, scope, dependencies, and acceptance evidence; include a stop/escalation condition only when a real boundary exists.
6. Put reversible preparation and verification before costly commitments. Add checkpoints only for actual evidence or authority dependencies, honoring existing authorization rather than re-requesting it.
7. Keep committed work separate from proposals and conditional future work. When evidence changes a dependency, update affected steps and preserve unaffected decisions.

## Result
Use a compact goal, outcome-oriented sequence, meaningful checkpoints, next executable unit, and material deferred items. A plan is sufficient when the next unit can start coherently; continue execution when requested rather than ending with the plan.

Use a specialized method only if an unresolved requirement, design, or evidence problem warrants it. These are not required stages for every plan.
